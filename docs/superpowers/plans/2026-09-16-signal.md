# Agent Hive — sinal verde / amarelo / vermelho: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A global runtime `signal` (`green` / `yellow` / `red`) the orchestrator consults before opening a new job. Green is today's behavior. Yellow lets live workers finish but opens nothing new. Red is manual mode: nothing new opens and each live worker gets a `paused` mark when its current turn ends (`Stop` hook), cleared when the signal leaves red or someone types in that worker's terminal. Nothing is ever killed mid-turn. The signal is set by three buttons in the dashboard header and by `POST /signal`, and it survives a restart because it lives in `.hive/state.json`.

**Architecture:** `State.signal` is a new field of the reducer state (`initialState` starts at `green`); `Slot.paused` is a mark, never a status. `canStart(signal, slots)` in `src/orchestrator.ts` is the one pure gate: green **and** a `vazio` slot that is not draining. `fill` returns its input untouched when `canStart` is false, so `poll`, `setMax`, `exit`, `SessionEnd` and the new `setSignal` event all inherit the gate without their own checks. `Stop` under red writes `paused: true` and `lastEvent = 'pausado: sinal vermelho'`; `UserPromptSubmit` / `PreToolUse` clear it; `setSignal` clears it on every slot when the new signal is not red, then runs `fill`. `loadState` normalizes a missing or unknown `signal` to `green`. `server.ts` adds `POST /signal` on the `POST /config` pattern. The UI adds three buttons plus a hint in the header and a ` · pausado` / dimmed card.

**Tech Stack:** unchanged — Node 24, pnpm, TypeScript strict (`tsc` only, ESM `nodenext`, `.js` import extensions), Electron, Express 5, `node:test` + `node:assert/strict`.

**Spec:** `docs/superpowers/specs/2026-09-16-signal-design.md` (extends `docs/superpowers/specs/2026-09-15-agent-hive-design.md`).

## Global Constraints

- All v1, setup and boards constraints hold (immutable reducer, `execFile` argv arrays, Portuguese UI copy, conventional commits without `Co-Authored-By`, no machine-specific values; `@me` / project 6 is only a manual-test fixture).
- `main.ts`, `run.ts`, `hive.ts`, `config.ts`, `hooks-settings.ts`, `spawn.ts`, `board.ts`, `src/boards/*` do not change. Hooks, spawn, board adapters, `hive.config.json` and the setup form are untouched.
- The signal lives only in `State.signal` (persisted in `.hive/state.json` by the existing `saveState`); never in `hive.config.json`, `SetupBody` or the setup form.
- `canStart` is the single spawn gate: `fill` is the only place a `spawn` effect is created and it consults `canStart` first. No other reducer branch reads the signal except `Stop`.
- No signal emits `kill`, sends text to a terminal, or changes a slot's `status`; `paused` is a mark only and never counts in `N/M workers ativos`.
- `POST /signal` follows `POST /config`: `requireLive` (409), then validation (400 with `signal must be one of: green, yellow, red`), then `dispatch` and `{ ok: true }`.
- Every Portuguese UI string is exactly as the spec writes it: `verde`, `amarelo`, `vermelho`, `sem jobs novos`, `modo manual`, ` · pausado`, `pausado: sinal vermelho`. Code comments in English.
- ESM with `.js` import extensions; no new runtime dependencies; source files under 400 lines, functions under 50 lines.
- `test/setup.test.ts` keeps its fake factory and `maxConcurrent: 0`, so nothing spawns.
- `pnpm test` must stay green after every task (94 tests today → 104 at the end).

```ts
import { readFile, rename, writeFile } from 'node:fs/promises';
import { join } from 'node:path';
import { initialState, SIGNALS } from './orchestrator.js';
import type { Signal, State } from './types.js';

const STATE_FILE = 'state.json';

const isSignal = (value: unknown): value is Signal => SIGNALS.includes(value as Signal);

export async function loadState(hiveDir: string, maxConcurrent: number): Promise<State> {
  try {
    const parsed = JSON.parse(await readFile(join(hiveDir, STATE_FILE), 'utf8')) as State;
    if (Array.isArray(parsed.slots) && Array.isArray(parsed.queue) && Number.isInteger(parsed.maxConcurrent)) {
      // files written before the signal existed have no `signal`; anything unknown reads as green
      return { ...parsed, signal: isSignal(parsed.signal) ? parsed.signal : 'green' };
    }
  } catch {
    // missing or corrupt: start fresh
  }
  return initialState(maxConcurrent);
}

export async function saveState(hiveDir: string, state: State): Promise<void> {
  const path = join(hiveDir, STATE_FILE);
  const tmp = `${path}.tmp`;
  await writeFile(tmp, JSON.stringify(state, null, 2));
  await rename(tmp, path);
}
```
